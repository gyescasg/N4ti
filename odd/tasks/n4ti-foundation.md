# N4ti foundation: context budgets and progress integrity
Scope: N4ti foundations, compatible rename, manual save/resume and selective retrieval. Route: inline with independent verification for shared CLI and persisted-state risk. Runner: Windows PowerShell 5.1.
Delivery: local files only (workspace had no Git repository at the time); no commits or publishing. Estimated change: approximately 350 authored lines. Engram mirror: odd/n4ti-foundation/tasks. User requirements are paraphrased in English for the public repository.

## Specs
- S1: User goal: N4ti must be lightweight and optimize tokens in a smart way. This slice enforces the existing estimated budget over the entire generated context/task packet, preserves mandatory documents and the assigned task, and rejects impossible budgets before writing output. No additional runtime dependency or claim of exact model-token accounting.
- S2: User goal: optionally save memory of progress made across projects. This slice fixes the diagnosed result-name collision and invalid task/agent acceptance, prevents closing an unrelated task from overwriting active-task state, and fixes the reproduced second-task ID formatting failure needed to track multiple tasks. Existing result payload remains reported, not automatically verified.
- S3: User authorized proceeding with the next step. Regression tests must exercise public CLI commands in disposable projects, check exit status/output/persisted state, and retain the existing smoke workflow. Document changed behavior and remaining limitations.
- S4: User goal: rename the project to N4ti. Renaming and save/resume commands are subsequent slices, not silently mixed with this foundational fix; preserve GY paths and commands here.
- S5: User approved continuing and selected the recommended storage option `N4ti/`. Fresh installs use N4ti/; existing GY/ stores and contents remain intact. n4ti and gy entrypoints address the same selected store. Both stores present, or malformed existing storage, must refuse before mutation. Package-owned branding/instructions use N4ti without replacing unrelated user text.
- S6: Implement optional manual `save -Summary ... -Next ... [-Id task] [-Files ...] [-Tests ...] [-Risks ...]` and read-only `resume [-Id task] [-Budget ...]`. Save one unique atomic JSON checkpoint per call, mark evidence as reported/unverified, and preserve literal text. Omitted task ID means project-level checkpoint. Resume selects the latest matching checkpoint within this installed project and refuses insufficient budgets rather than truncating. No automatic transcript capture, secret-detection promise, remote service or new runtime dependency.
- S7: Preserve prior tests using an explicit legacy fixture, add fresh-store/alias/upgrade/ambiguity/checkpoint/privacy-policy regressions, and fix the reproduced second-decision numeric-format failure needed for repeated project decisions. Update installation and daily-use documentation. Do not relocate existing GY memory automatically.
- S8: User asked to continue toward the smart token-optimization goal (S1). This slice adds accent-insensitive Unicode lexical matching, stronger title/tag/path signals, explicit `-IncludeArchive` for search/context/task-packet, and exact rendered-content deduplication for optional documents only. Explicitly assigned archived tasks remain required; mandatory documents are never deduplicated or silently omitted. Search lists all matching sources. Preserve complete-output budgets and source text; no embeddings, new dependencies, semantic summarization or claimed universal savings.
