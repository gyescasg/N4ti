# N4ti token savings: measurable, model-independent context reduction
Objective: reduce tokens N4ti hands to any CLI/IDE without depending on a model, API, tokenizer or new runtime. Branch: feat/token-savings. Runner: Windows PowerShell 5.1 (`Test-N4ti.cmd`).
Delivery: ask-on-risk; work-unit commits only after user approval. Engram mirror: odd/n4ti-token-savings/tasks. User requirements are paraphrased in English for the public repository.

## Specs
- S1 Independence (applies to every task): User requirement: N4ti must not depend on any model, API, tokenizer or embeddings; it must be usable from any CLI or IDE to save tokens. Embeddings may be considered in the future, not now. No model APIs, tokenizers, embeddings or new dependencies; estimates stay deterministic and local.
- S2 Phase 0 baseline: a read-only `bench` command measures, for one or more queries, the context pack exactly as `context` would build it (same budget, ranking and header) and reports estimated tokens, characters, included and omitted documents, corpus size, always-loaded cost and the prefix shared across packs. It writes nothing and fails exactly like `context` when required content does not fit.
- S3 Phase 1 (planned): remove CORE/STATE double load from host protocol; cache-stable pack order (volatile query/count/time last, no timestamp); linear value-per-token packing.
- S4 Phase 2 (planned): section-level retrieval by `##` headings; one-level progressive disclosure (index of omitted items + `get <ID#section>`); deterministic BM25F ranking.
- S5 Phase 3: `supersedes`/`expires` catalog fields; enforced subagent result cap; delta packs (`context -Since`). Approved design (L11):
  - S5a: optional per-document `supersedes` (array of ids) and `expires` ("yyyy-MM-dd", local date). Superseded or expired documents are excluded in `Get-DocumentRows` (search, context, bench, task-packet); `-IncludeArchive` includes them; `get` still returns them; they are not listed in the "Not included" index. A superseded or expired mandatory document is an error, like archive. `validate` reports unknown targets, self-reference, cycles and bad dates. `new-decision -Supersedes <ids>` writes the catalog field.
  - S5b: `record-result` estimates before writing and rejects above the cap, writing nothing. Cap from `orchestration.json` `resultTokenCap`, default 800. `validate` keeps only warning for existing over-cap result files. The cap number appears in the task-packet contract and host protocol step 6.
  - S5c: every `context` stores `.runtime/packs/<id>.json` with a hash per delivered unit and prints the pack id at the end. `context -Since <id>` delivers only new or changed units; unchanged units become an "already delivered" index line; unchanged mandatory documents are not repeated. No clock or git dependency. Keep only the last 20 manifests.
